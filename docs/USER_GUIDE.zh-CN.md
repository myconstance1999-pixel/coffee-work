# Coffee Work 1.8 使用说明

Coffee Work 是菜单栏的咖啡杯工具。它管理电脑的空闲睡眠与屏幕显示请求，不管理 Codex 的任务执行。任务结束、计时到期或关闭保持，都不会让它强制关机、重启或取消任务；它只是撤销自己的保持请求，之后由 macOS 和其他应用决定是否睡眠。

本手册对应 **Coffee Work 1.8 源码发布版**：需要按 [README.md](../README.md) 自行构建，本地构建为 ad-hoc 签名，没有 Developer ID 签名或已公证的可下载版本。1.5 的旧手册（保留原文）见 [docs/history/USER_GUIDE.v1.5.zh-CN.md](history/USER_GUIDE.v1.5.zh-CN.md)。

按 [README.md](../README.md) 的 **Build** 构建，并按 **Install (manual)** 安装后，从 `$HOME/Applications` 打开 **Codex Work Mode.app**，点击菜单栏咖啡杯即可使用。Coffee 不会自行安装登录启动项，也不会改动你原有的系统设置。

## 按场景选择

| 你的需求 | 使用方法 | 会发生什么 |
| --- | --- | --- |
| 图书馆阅读、查资料，希望屏幕长亮 | **保持屏幕显示**，选择时长或**直到我关闭** | 保持显示并防止系统空闲睡眠；电池和低电量模式下也可使用；自动屏保会暂缓 |
| 终端计算、下载或其他后台任务，不需要亮屏 | **手动后台计时** | 保持系统清醒，但允许屏保与息屏；电池也可使用 |
| 插电让已连接的 Codex 任务长时间运行 | 开启**自动保持后台工作（接通电源）** | 仅在检测到有效工作状态时自动保持后台清醒；不会自动保持屏幕显示 |
| 需要 Computer Use 操作桌面 | 可显式开启**保持屏幕显示** | 避免空闲息屏，但不保证任意应用或任务成功，也不会绕过锁屏 |
| 想主动看屏保 | **立即启动屏保** | 结束显式屏幕显示保持并启动 macOS 屏保；保留后台请求，但它们仍受锁屏等规则约束 |
| 日常通勤 | 不需要保持时结束手动计时和屏幕显示保持 | 拔电会立即撤销自动后台保持；手动请求不会因拔电而自动取消 |

长时间亮屏会增加耗电。低电量模式与是否保持显示是两个独立选择：Coffee 不会为了亮屏而关闭低电量模式。

## 亮屏与后台计时是独立的

**保持屏幕显示**提供 30 分钟、1／4／8 小时、自定 1～24 整小时，以及“直到我关闭”。**手动后台计时**提供 1／4／8 小时与自定 1～24 整小时。两者可以同时运行，各自有停止按钮。

- 停止显示保持，不会顺带取消后台计时或自动后台保持。
- 停止后台计时，不会顺带取消显示保持。
- 有截止时间的请求在锁屏、睡眠或切换用户时暂停；恢复后只继续剩余时间，不补时。暂停期间到期后不会重新启动。
- “直到我关闭”没有截止时间，但仍会在锁屏、睡眠或会话不可用时暂停，恢复合适的会话后继续。退出或重启 Coffee 后不会自动恢复这项请求。
- 退出 Coffee 会结束它自己的计时与保持，不会退出 Codex。撤销保持后，系统可能很快进入屏保或息屏，并不一定重新等完整个空闲时长。

## 自动后台保持如何判断

需要自动开关开启、外接电源、可信的当前用户会话，以及本机受支持的 Codex hooks 提供有效工作状态。电池充满、达到充电上限或暂停充电，仍属于外接电源。

| 状态变化 | 自动后台保持 |
| --- | --- |
| 未锁屏时最后一个任务结束或等待批准 | 已存在的自动保持可延续 120 秒宽限，然后释放 |
| 拔电或无法识别电源 | 立即释放，不等宽限 |
| 锁屏时仍有有效工作状态，且接电、当前会话可信 | 可继续后台保持；这不等于 Computer Use 可以操作锁定的桌面 |
| 锁屏时任务结束、等待批准或状态失效 | 立即释放，不等宽限 |
| 系统即将睡眠、切换用户或会话不可信／未知 | 释放；恢复后重新判断 |

120 秒只是撤销保持之前的宽限，不是“120 秒后关机”或“保证那时睡眠”。真正睡眠可能暂停本机计算和网络连接；能否恢复取决于任务与系统。

**自动检测有范围限制。** 只打开 Codex 不算正在工作；独立 CLI、云端任务，以及没有受支持本机 hooks 的 Work／圆点任务，不能保证自动识别。请在**更多状态与日志**查看已连接任务及自动保持原因。未识别的后台任务可显式使用手动后台计时。

## Computer Use 实机结果与限制

2026 年 10 月 9 日，在这台 Mac 上进行了不触碰键盘、触控板或 Touch ID 的测试，通过系统状态记录、Calculator 的新计算结果和截图核对：

| 测试 | 观察结果 | 可以得出的结论 |
| --- | --- | --- |
| 主动锁屏 | 约 2 秒后会话解锁，随后完成 `8 × 9 = 72` | 当前 Computer Use 环境成功恢复过一次；不是持续保持锁定状态操作 |
| 息屏并锁定 | Computer Use 恢复亮屏、解锁，随后完成 `9 × 9 = 81` | 当前环境成功从息屏恢复过一次；屏幕没有一直保持关闭 |
| 主动屏保并锁定 | Computer Use 报告自动解锁失败，屏保和锁定状态仍在 | 两次试验均未继续 GUI 操作，需要手动解锁 |

因此，**当前不应依赖屏保状态下的无人值守 Computer Use**。若需要 GUI 自动操作，保持屏幕显示可避免空闲息屏这一触发因素；不要把它当作解锁能力或长期可靠性保证。

自动恢复来自当前 Computer Use 环境，**不是 Coffee 在解锁或代输密码**。本轮没有修改锁屏、密码、权限或 Locked Use 设置。单次成功不代表所有应用、所有任务和以后每次运行都成功；这两次都是单次无人干预恢复成功，**不构成持续锁屏／息屏下 GUI 工作的能力或可靠性保证**。早先有两次测试由使用者手动解锁，未计入上述无人干预成功结果。

OpenAI 的 [Computer Use／Locked Use 说明](https://learn.chatgpt.com/docs/computer-use#locked-use) 与 [远程连接说明](https://learn.chatgpt.com/docs/remote-connections) 可用于理解能力边界；本手册中的表格记录本机实测，不代替官方的可用性与权限要求。

## 系统行为仍由你和 macOS 决定

- Coffee 不阻止你主动锁屏、睡眠或合盖，也不强制外接显示器模式下的 Mac 睡眠，不主动唤醒机器。
- 屏幕关闭、屏保、锁屏、整机睡眠是不同状态；你的密码策略可能在屏保或息屏时立即锁定。本机测试中确实发生了这种情况。
- 屏保启动按钮不承诺屏保永远亮着；后续锁屏和息屏仍遵循系统设置。
- 电池低电量／接电高功率是 macOS 的独立配置，退出 Coffee 后仍适用。菜单只是读取电源模式，不代表实际性能提升。
- 本轮未做实体拔插电源、低电量模式下长时间亮屏、合盖、快速用户切换验收；电池适用逻辑已通过代码与隔离测试，不能冒充这些实机项目已完成。
